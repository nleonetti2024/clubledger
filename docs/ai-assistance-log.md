# AI assistance log

The course asks that material AI assistance, validation work, rejected or revised outputs and
known limitations be recorded. This log does that.

**Tool:** Claude (Anthropic), used as a coding assistant in one working session on 2026-11-11,
plus the developer's own review afterwards.
**Role of AI:** proposed the project scope, architecture, code, tests, sample data and
documentation. Ran the tests, the evaluation and a browser walkthrough, and fixed defects.
**Role of the developer:** chose the project (a real need from a club president), reviewed
and accepted or changed the design, verified behavior, and is responsible for the submitted work.

## AI suggestions that were rejected or limited

| Suggestion / option | Decision | Reason |
|---|---|---|
| Let the LLM decide approve/reject | **Rejected** | Money decisions must be predictable, testable and accountable. AI only extracts fields. |
| Auto-approve expenses with no flags | **Rejected** | Violates retained human authority. Flags can miss things, so the treasurer still confirms. |
| Tune the offline reader until sample 09 is perfect | **Rejected** | That would overfit to test data and hide a real weakness. The flags already catch it. |
| Add a Dockerfile and cloud deployment | **Deferred** | It could not be tested in the build environment, and untested deployment instructions would be misleading. |
| Add RAG over the policy | **Rejected** | The policy is short and enforced by code. Retrieval adds complexity with no measurable gain. |
| Use the official `anthropic` SDK | **Changed** | Used the standard-library `urllib` instead, so the project has two dependencies and the HTTP layer is easy to mock in tests. |

## Limits of what the AI could verify
